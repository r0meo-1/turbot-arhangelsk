# АПРЕЛЬ тур — VK Mini App

Форма для сообщества **240310110**. Работает в существующем Flask-процессе `vk_bot.py`:

1. Клиент выбирает направление, вылет, дату, ночи, взрослых, возрасты детей и бюджет **на всю поездку**.
2. Видит сводку и отдельно подтверждает сохранение параметров.
3. Сервер проверяет подпись VK, ID приложения, пользователя, группу и время запуска, затем сохраняет черновик в существующую SQLite-таблицу sessions.
4. Клиент открывает чат и пишет **«Проверить заявку»**. Существующий бот продолжает с экрана review: отели, цены, изменение параметров и отдельная передача менеджеру.

Сохранение формы не отправляет сообщений и не создаёт лид. Повтор тех же параметров возвращает успех без перезаписи; другой активный подбор возвращает 409. В обычном браузере доступен предпросмотр с выключенным сохранением. Telegram Mini App остаётся отдельным каталогом `miniapp/`.

## Подключение

Код подготовлен, но приложение ещё не зарегистрировано и не подключено к сообществу.

1. Создать VK Mini App в кабинете разработчика от владельца сообщества. Сохранить числовой ID приложения.
2. На сервере в окружении **VK-сервиса** задать `VK_MINI_APP_ID` и `VK_MINI_APP_SECRET` (защищённый ключ именно приложения, не токен группы). Ключ хранить только на сервере. `VK_GROUP_ID` должен быть `240310110`.
3. Развернуть эту ветку обычным процессом проекта и перезапустить VK-сервис. До настройки ID/ключа API возвращает 503.
4. Указать HTTPS-адрес приложения для нужных платформ: `https://bot.r0meo1.ru/vk/miniapp/`. Это **целевой адрес после деплоя**, его доступность сейчас не подтверждена. Существующий nginx-шаблон уже проксирует `/vk/` в VK-сервис.
5. Добавить созданное приложение в сообщество 240310110 и настроить точку входа «Подобрать тур» средствами кабинета VK.
6. Открыть приложение из VK тестовым пользователем; проверить форму, сохранение, продолжение в чате, отсутствие заявки менеджеру до отдельного подтверждения. Проверить iOS, Android и веб-клиент.

Для завершения подключения нужны ID созданного приложения и доступ владельца к его настройкам. Защищённый ключ не отправлять в чат, не добавлять в git и не помещать в HTML/JavaScript.

## Локальный предпросмотр

Из корня репозитория: `python -m http.server 8080 --bind 127.0.0.1`, затем `http://127.0.0.1:8080/vk-miniapp/`.
Этот сервер отдаёт только статическую форму, отправка отключена без подписанного запуска VK.

## Проверки

`python -m pytest tests/test_vk_miniapp.py tests/test_vk_bot.py tests/test_miniapp_frontend_contract.py`

Проверяются подделанные/просроченные/дублирующиеся параметры запуска, неверный ID приложения/группы, отсутствие настройки, согласие, даты и числовые границы, ошибки хранения, SQLite-черновик без сообщений и лидов, повторное сохранение и продолжение существующего review.

Проверка внутри реального клиента VK и публикация не выполнены. В этой версии отели/цены и контакт с менеджером продолжаются в чате, а не внутри формы.

## Зависимости и источники

`vk-bridge.js` — локальная копия `@vkontakte/vk-bridge@2.15.0/dist/browser.min.js` из npm (через unpkg), лицензия MIT, рядом `VK-BRIDGE-LICENSE.txt`. Само приложение не загружает скрипты со стороннего CDN.

- VK Bridge: https://github.com/VKCOM/vk-bridge
- Проверка подписи по официальному Python-примеру VK: https://github.com/VKCOM/vk-apps-launch-params/blob/master/examples/python3.py

Приложение отправляет исходные параметры запуска только на свой сервер. Не включайте query string URL приложения в аналитические события или журналы доступа: там находится подписанный вход пользователя.
