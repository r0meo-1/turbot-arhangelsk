# АПРЕЛЬ тур — VK Mini App

Форма для сообщества **240310110**. Работает в существующем Flask-процессе `vk_bot.py`:

1. Клиент выбирает направление, вылет, дату, ночи, взрослых, возрасты детей и бюджет **на всю поездку**.
2. Видит сводку и отдельно подтверждает сохранение параметров.
3. Сервер проверяет подпись VK, ID приложения, пользователя, группу и время запуска, затем сохраняет черновик в существующую SQLite-таблицу sessions.
4. Клиент открывает чат и пишет **«Проверить заявку»**. Существующий бот продолжает с экрана review: отели, цены, изменение параметров и отдельная передача менеджеру.

Сохранение формы не отправляет сообщений и не создаёт лид. Повтор тех же параметров возвращает успех без перезаписи; другой активный подбор возвращает 409. В обычном браузере доступен предпросмотр с выключенным сохранением. Telegram Mini App остаётся отдельным каталогом `miniapp/`.

## Статус production

Приложение **«Апрель Тур»**, ID **54475121**, развёрнуто на production по адресу `https://bot.r0meo1.ru/vk/miniapp/`.

Последний production deploy для `main` подтвердил:

- установка `VK_MINI_APP_ID` и `VK_MINI_APP_SECRET` на сервере;
- успешный `nginx -t`;
- доступность `/vk/health`, `/vk/miniapp/` и `/vk/miniapp/app.js` извне;
- наличие production-контракта `budgetScope: 'total'` и `source: 'vk_mini_app'` во фронтенде;
- корректный HTTP `401` на `/vk/miniapp/draft` без валидной VK-подписи;
- итоговый smoke `Public Mini App routes and auth rejection smoke: ok`.

**Не подтверждены только платформенные шаги внутри VK:** привязка приложения к сообществу **240310110**, наличие точки входа «Подобрать тур» и полный реальный запуск из авторизованного клиента VK.

## Подключение в VK

1. Использовать существующее приложение **54475121**, не создавать дубликат.
2. В кабинете приложения указать HTTPS-адрес для нужных платформ: `https://bot.r0meo1.ru/vk/miniapp/`.
3. Подтвердить, что приложение привязано к сообществу **240310110**.
4. Настроить в сообществе точку входа **«Подобрать тур»**.
5. Открыть приложение из VK тестовым пользователем и заполнить форму.
6. После сохранения открыть чат сообщества и написать **«Проверить заявку»**. Бот должен продолжить именно сохранённый подбор на экране review.
7. Проверить отсутствие заявки менеджеру до отдельного подтверждения пользователя.
8. Повторить реальный клиентский smoke на iOS, Android и веб-клиенте VK.

Не указывать в качестве адреса размещения `https://vk.ru/app54475121` — это ссылка запуска в VK, а не URL приложения. Не использовать и корень `https://bot.r0meo1.ru`: рабочий Mini App расположен по полному пути `/vk/miniapp/`.

Серверная реализация рассчитана на `VK_GROUP_ID=240310110`. `VK_MINI_APP_SECRET` — защищённый ключ именно приложения, а не токен группы; он хранится только на сервере и не должен попадать в чат, git, HTML или JavaScript.

Перед реальным запуском также проверить, что production nginx и `deploy/vk-turbot.service` используют безопасное логирование: query string и Referer с подписанными параметрами VK не должны попадать в обычные access logs. Если перед сервером есть другой proxy/CDN, проверить его журналы отдельно.

## Локальный предпросмотр

Из корня репозитория: `python -m http.server 8080 --bind 127.0.0.1`, затем `http://127.0.0.1:8080/vk-miniapp/`.
Этот сервер отдаёт только статическую форму, отправка отключена без подписанного запуска VK.

## Проверки

Основные серверные и контрактные тесты:

`python -m pytest tests/test_vk_miniapp.py tests/test_vk_bot.py tests/test_miniapp_frontend_contract.py tests/test_vk_miniapp_review_return.py`

Полный browser roundtrip VK Mini App:

`python -m pytest -q tests/test_vk_miniapp_e2e.py`

Проверяются подделанные/просроченные/дублирующиеся параметры запуска, неверный ID приложения/группы, отсутствие настройки, согласие, даты и числовые границы, ошибки хранения, SQLite-черновик без сообщений и лидов, повторное сохранение, возврат из Mini App командой **«Проверить заявку»** и продолжение существующего review.

Автоматические тесты не заменяют финальный smoke внутри реального авторизованного клиента VK.
